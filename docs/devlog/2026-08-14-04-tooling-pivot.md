# Синк №4 — Разворот на инструменты (демо-вьюер, чат, реестр, пекарь)

Дата: 14.08.2026. Решение пользователя (в1): фичи на стоп, строим инструменты
для разработки/дебага. Конечный сюжетный мир: генерация печёт объекты в реестр
(`.dfo`) и карты (`.dfw`), игра расставляет готовое, ничего не рождается в кадре.
Агенты работают и дебажат в демо-вьюере, а не в игре.

## Сделано этим синком

- **Каркас редактора + свободная камера** (`AppMode::Editor`, `cc50491`): 6DOF
  облёт, тумблер «встать игроком» (Tab), дверь `DFN_EDITOR`/`DFN_EDITOR_CAM`.
- **Контракт раскладки карт** (`docs/MAP_LAYOUT.md`): `assets/maps/<категория>/`
  с манифестами `.map` (в git) и чат-файлами `.chat.jsonl` рядом; печёный `.dfw`
  вне git, пересобирается при первом запуске. Заложен ДО демок по требованию
  пользователя.

## Синк контракта IRenderer (правило 26) — три хука B28

Зона render-hooks добавила АДДИТИВНО к замороженному контракту `IRenderer`
(`aecb0d0`), запись в UPD `IRenderer.h` сделана там же; эта строка — обещанная
за лидом (docs — зона лида):

1. **`frame_stats()` → `RenderFrameStats{scene_draws, scene_triangles,
   backend_draws}`.** Честный предел bgfx: `getStats()` даёт число дро-коллов, но
   НЕ примитивов, поэтому `scene_triangles` считается на CPU из index_count
   мешей (точно для индексированных, без теневых перерисовок). `backend_draws` —
   полная нагрузка всех вью (122 против 53 сцены на стенде): одно — сложность
   сцены, другое — честная нагрузка GPU.
2. **`set_wireframe(bool)` → `bgfx::setDebug(BGFX_DEBUG_WIREFRAME)`.** Флаг
   ГЛОБАЛЬНЫЙ и разлиновал бы полноэкранный upscale-квад в чёрное — поэтому в
   режиме каркаса сцена рисуется прямо в бэкбуфер, present пропускается;
   аспект корректен, т.к. проекция строится из аспекта фреймбуфера. Выкл по
   умолчанию, ноль стоимости.
3. **`center_pick()` → `RenderPick` + `DrawParams::pick_id`.** Вариант А: CPU-луч
   из центра против ограничивающих сфер (уже считаются для теневого куллинга).
   Платформа не знает про EntityId/LOD, поэтому `pick_id` штампует сабмиттер
   (engine/render); `triangles` — счёт РЕАЛЬНО отрисованного меша, т.е.
   выбранного в кадре LOD. Вариант Б (id-пасс + readback) отложен как эскалация.

Приёмка: `DFN_WIREFRAME=1`/`DFN_FRAME_STATS=1`, обе руки один бинарник; кадр
`docs/acceptance/render-B28-wireframe.png`. Передано зоне app/editor: читать
`frame_stats()`/`center_pick()`, штамповать `pick_id = EntityId` на сабмите,
рисовать оверлеи поверх.

## Браузер карт редактора (зона app) — контракт docs/MAP_LAYOUT.md

Вход в «Играть» и в «Редактор» открывает НЕ карту, а браузер: категории (папки
`assets/maps/<категория>/`) → карты (`.map` в папке) → открыть. Прыжок сразу в
карту был названной пользователем ошибкой первого каркаса и снят.

- **`MapCatalog` (engine/app)** сканирует `assets/maps` по фиксированному списку
  категорий (в40): пустые показываются пустыми. Парсит транзитный манифест
  `.map` (`key = value`): `name`, `zone`, `size_chunks`, `source`, `description`;
  неизвестные ключи игнорирует (формат — контракт лида, не расширяю).
- **Меню** двухуровневое: `MenuPage::Categories` → `CategoryMaps`. Обе кнопки
  корня зовут один браузер; `MenuAction::OpenMap` + `browse_target()` решает,
  играть карту или летать над ней (В39: смена карты одним пикером, в игре — без
  дебаг-инструментов).
- **`App::open_map()`** разрешает `source`: `stand:Testbed|Forest` грузит стенд
  (мост до пекаря), `dfw:<файл>` — честная ошибка на экран (пекаря нет), не
  молчание.
- **Двери:** `DFN_OPEN_MAP=<категория>/<карта>` грузит карту минуя браузер
  (имя НЕ `DFN_MAP` — то занято щупом экрана карты render и гейтом Tour);
  `DFN_EDITOR=1` без карты открывает браузер редактора.
- **Сим для зоны chat:** `App::current_manifest()` → `const MapManifest*`
  (`category`/`file_stem`/`zone`), из него chat выводит путь чат-лога
  `assets/maps/<category>/<file_stem>.chat.jsonl`.
