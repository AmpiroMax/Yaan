# Аудит кода инструментов редактора

Заказан пользователем 18.08.2026 дословно: «у меня серьезная настроенность в том,
что текущий код инструментов стал спагетти кодом. У тебя нет отдельного класса
под инструменты, нет четких интерфейсов взаимодействия и прочее. Если бы они
были, нельзя бы было поймать ошибки, что я сразу два инструмента в руке держу и
прочее.»

**Претензия верна целиком.** Ниже — числа, потом причина, потом что с этим
делать. Ничего не сглажено: аудит, который заканчивается словами «в целом
неплохо», не стоит времени на чтение.

## Причина, а не симптом

`EditorTool` — это **ярлык**, а не объект. Он лежит в `EditorUi`, а всё
поведение инструмента разбросано по местам, которые обязаны про него помнить:

- щелчок левой кнопкой — в `run()`, строка ~4885;
- проход «что под прицелом» и призрак — в `update_build_tool()`, ~3718;
- мазок кистью — в `update_editor_tools()`, ~4262;
- подпись на экране — снова в `run()`, ~5784;
- панель настроек — в `wire_editor_panels()`, ~4093;
- дверь выбора режима — снова в `run()`, ~4741.

Шесть мест, каждое со своим `if` или `switch`. **Ни одно из них не знает про
остальные пять.** Добавляя инструмент, надо вспомнить все шесть; забыв одно,
получаешь инструмент, который наполовину работает — и именно это происходило
весь день:

- **«держу сразу два инструмента»** — щелчок взводился условием
  `режим постановки ИЛИ открыт список объектов`, а кисть висела на той же
  кнопке отдельно. Два владельца одной кнопки, и никто не спрашивал другого.
- **«деталь остаётся в руках»** — загрузка призрака стояла в конце функции с
  тремя ранними выходами, и вне режима редактора не вызывалась вовсе.
- **«покраска и высота странно взаимодействуют»** — это ОДИН объект
  `TerrainBrush` с полем `mode`, показанный как ДВА инструмента на полосе.
  Полоса и переключатель в панели задают одно состояние из двух мест.

- **«что за порода выбирается, когда я открываю меню кисти? она ни на что не
  влияет»** — и она действительно ни на что не влияет. Список пород живёт в
  панели КИСТИ, а посадка вызывается ровно из одного места: `plant_dab_here` на
  Shift+ЛКМ **внутри обработчика инструмента ПОСТАНОВКИ** (`App.cpp:4887`).
  То есть галочки стоят у одного инструмента, а читает их другой — и только
  если человек догадается переключиться и держать Shift. «Посадки» нет среди
  пяти инструментов вовсе: её органы управления у кисти, её действие у
  постройки, а хозяина нет ни у чего.

Все четыре — не разные ошибки. Это один и тот же дефект: **у инструмента нет
единственного владельца своего поведения**, поэтому исключительность
инструментов не следует из устройства, а держится на договорённости, которую
надо соблюсти в шести местах.

## Что предлагается

Интерфейс `IEditorTool` — по классу на инструмент, и один список активных.
Контракт минимальный, но ПОЛНЫЙ: если инструмент не отвечает на вопрос, значит
он этого не делает — а не «где-то ещё в App это дописано».

```
class IEditorTool {
    // ЧТО ЭТО. Имя для полосы, значок, подсказка внизу кадра.
    virtual ToolIdentity identity() const = 0;

    // ЧТО ОН ДЕЛАЕТ ПО ЩЕЛЧКУ И ПО ПРОТЯЖКЕ. Один владелец кнопки.
    virtual void on_press(const ToolAim& aim, ToolWorld& world) = 0;
    virtual void on_drag(const ToolAim& aim, float dt, ToolWorld& world) = 0;
    virtual void on_release(ToolWorld& world) = 0;

    // ЧТО ОН РИСУЕТ В МИРЕ, пока выбран: призрак детали, кольца кисти.
    virtual void preview(const ToolAim& aim, ToolPreview& out) = 0;

    // ЕГО СОБСТВЕННЫЕ НАСТРОЙКИ — и ничьи больше.
    virtual void draw_settings() = 0;

    // ЕГО ДАЛЬНОБОЙНОСТЬ, ограниченная общим потолком.
    virtual float max_reach_m() const = 0;

    // ВЫБРАЛИ / ОТПУСТИЛИ. Здесь инструмент обязан всё за собой убрать —
    // именно это место отсутствовало, когда деталь оставалась в руках.
    virtual void on_selected(ToolWorld& world) = 0;
    virtual void on_deselected(ToolWorld& world) = 0;
};
```

Три свойства, которые из этого следуют **по построению**, а не по внимательности:

1. **Два инструмента одновременно невозможны.** Активный указатель один;
   щелчок уходит ему и только ему. Нет места, где второй мог бы подписаться.
2. **Инструмент убирает за собой.** `on_deselected` вызывается ровно один раз
   и ровно в одном месте — там, где меняется активный указатель.
3. **Настройки не разъезжаются с выбором.** Панель рисует активный инструмент
   сам; переключателя, задающего то же состояние из второго места, нет.

## Что это НЕ чинит

Аудит обязан говорить и это. Перенос в интерфейс не исправит:

- `App::run()` в 1926 строк — она уменьшится, но останется слишком большой;
- хранение земли сеткой 2 м (отдельный заказ пользователя, зона world);
- то, что `App.cpp` в восемь раз длиннее собственного правила 21.

Разбор `run()` — отдельная работа, и делать её одним заходом с интерфейсом
инструментов нельзя: это две правки в одном доказательстве.

## Что именно стало невозможным по устройству

- **Два инструмента в руке.** Один `active_` в `EditorToolbox`; `update()`
  вызывает `active()` и НИ РАЗУ не обходит список. Проверено счётчиком нажатий
  у каждого инструмента: сумма после одного щелчка равна 1 (контрфакт «раздать
  всем» — 3 упавших случая из 14).
- **Уборка за инструментом.** `on_deselected` зовётся из `select()` и больше
  ниоткуда; `select()` — единственный, кто пишет `active_`.
- **Настройки ≠ выбор.** `click_settings()` физически не пишет `active_`
  (контрфакт «пусть пишет» — 3 упавших случая).

## Чего этот заход НЕ починил

- `App.cpp` — 6409 строк (было 6358; ушли два switch, пришли крючки мира и
  штабелирование). Правило 21 по-прежнему нарушено, разбор `run()` — отдельная
  работа, и делать её одним заходом с интерфейсом инструментов нельзя.
- `EditorUi.cpp` — 1173 строки (было 1238). Тоже выше 800.
- ШТАБЕЛИРОВАНИЕ БЕЗ ПОСТРОЙКИ. Инструмент теперь предлагает верх той
  расстановки, в которую упёрся прицел, но судья принимает опору на другую
  деталь ТОЛЬКО внутри одной группы (`Scene.cpp`: `if (!p.group.empty())` и
  `placements[j].group != p.group`). Значит: строишь с группой — работает;
  ставишь одиночки — судья ответит «hovers above the ground». Это правило
  ЗОНЫ world и контракт судьи, я его не менял. Обе половины зафиксированы
  рукавом `app_build_tool` («без группы судья штабель НЕ принимает — и это его
  правило, не наше»).
