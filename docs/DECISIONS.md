# Daggerfall N — сводный документ решений

Итог гриллинг-сессии [grill_sessions/initial-planning.md](grill_sessions/initial-planning.md): 81 вопрос, 11 раундов. Здесь — только принятые решения. Обоснования, отклонённые варианты и ресёрч — в самой сессии, номера вопросов (Qn) ведут туда. Все численные константы — в [NUMBERS.md](NUMBERS.md), здесь чисел нет намеренно.

**Статус: утверждён пользователем, является основой для техспек агентов.**

---

## 1. Видение

Игра в духе The Elder Scrolls. От **Скайрима** — игровой опыт: управление, взаимодействие с миром, ощущение боя. От **Даггерфола** — визуал: низкое разрешение рендера, ограниченная палитра, атмосфера. Полноценные 3D-модели со скелетной анимацией, не спрайты (Q4, Q9, Q10).

Главный принцип дизайна: **пустота — наш враг**. Плотность содержимого важнее площади мира (Q12, Q41).

Проект **личный**, не на публикацию: без Steamworks, достижений, облачных сохранений (Q60). Код на 100% агентский, с нуля до релизного билда; пользователь — геймдизайнер и читатель кода, но не автор (Q5, Q13).

**Формат музыки и как она попадает в память** (заказ владельца через музыкальную сессию, 27.08). Музыка — **Ogg Vorbis q5–q6**: MP3 отпал не по качеству, а потому что его паддинг кодера кладёт щель в каждую петлю. Встроенных декодеров Vorbis у miniaudio нет, поэтому в сборку добавлен **stb_vorbis v1.22** (Шон Барретт; MIT либо public domain) — он лежит внутри уже прибитой копии miniaudio (`extras/stb_vorbis.c`), и берётся оттуда, а не переносится в `third_party/`: один пин, одна версия, одна родословная (правило 24).

**Музыка декодируется ЦЕЛИКОМ в память, и это принятое решение, а не недосмотр.** Замер на заглавной теме (96.0 с, стерео, 1.4 МБ на диске): 102 мс на загрузку, 32.3 МБ в памяти как f32 на частоте устройства. Это цена ОДНОГО трека, и она куплена за отсутствие второго пути загрузки. Она не масштабируется, и число известно: четыре четырёхминутных слоя адаптивной музыки — около 370 МБ. Стриминг — см. §7.

## 3. Архитектура

**Раскладка:** `engine/` + `games/daggerfall_n/`, по образцу Quicky (Q26).

**Слои движка** (зависимости строго вниз): `core` → `platform` → `render` → `physics` → `anim` → `world` → `gameplay` → `editor` → `app` (Q27).

**Паттерн адаптера — единообразно** (Q30, Q31, Q62): каждая платформенная подсистема — интерфейс + рабочий бэкенд + null-бэкенд. `IRenderer` (bgfx/null), `IPhysics` (jolt/null), `IAudio` (miniaudio/null), `ILlm` (llama/null). Null-бэкенды — не заглушки, а рабочие режимы: headless-тесты, игра без LLM.

**Симуляция:** фиксированный шаг, рендер без ограничения с интерполяцией (Q32).

**Мир:** регион со стримингом чанков, тестируется на малом куске (Q12). Генерация процедурная, детерминированная по сиду, **оффлайн**: генератор — инструмент, мир сохраняется на диск, игра только читает, редактор правит (Q13). Данжи — отдельные сцены, процедурные из рукотворных префабов (Q13, Q43).

**Формат мира:** свой бинарный, секционный (магия + версия + секции тег/длина). Запрещены `memcpy` структур и неявный порядок байтов; little-endian явно (Q18, Q49).

**Сохранения:** слоты + автосейв на входе/выходе данжа; тот же секционный формат; **дельта от сгенерированного мира, не копия**; миграция версий с первого дня (Q56).

**Контент:** мир — бинарь; предметы, статы, диалоги, лут — текст в git; в C++ не хардкодится. Локализация с первой строки, оба языка (Q29, Q59).

**Шейдеры:** компиляция целью CMake + горячая перезагрузка в отладочной сборке (Q50).

## 4. Геймплей (каркас)

- Первое лицо, жёстко (Q8)
- Пиксельный вид: рендер в низкое разрешение + целочисленный апскейл, палитра опционально флагом (Q9)
- Бой: ЛКМ удар / ПКМ блок, урон — бросок кубов по статам (Q10)
- Взаимодействие: явно помеченные интерактивные объекты с подсветкой; без физической песочницы (Q11)
- Статы: даггерфоловские атрибуты + ~12 навыков, прокачка по использованию (Q42)
- Игровой цикл: процедурные задания гильдий (агенты) + рукотворные квесты (пользователь) (Q40)
- NPC: статичные функции на старте; расписание дня заложено (позиция NPC — компонент, не запись чанка) (Q44)
- Транспорт: ходьба/бег с выносливостью; лошадь и быстрое перемещение заложены архитектурно (компонент «открыто» в сохранении) (Q47)
- UI старта: подсказка наведения + полоски здоровья/выносливости; стек экранов и навигация геймпадом заложены сразу (Q58)
- Метрики мира: стенд и регион имеют РАЗНЫЕ контракты плотности — числа в NUMBERS.md (Q41, Q45, Q46)

## 5. NPC, LLM и озвучка

**API управления NPC — фундамент** (Q70, требование пользователя, повторённое дважды): типизированное перечисление `NpcAction`; не существует способа управлять NPC мимо него. Скрипт, LLM, тесты, редактор используют один и тот же канал.

**LLM** (Q62–Q67): скрипты — основа, LLM — подключаемая фича. Намерение задаёт скрипт, слова даёт LLM. Сейчас только реплики; планирование поведения — позже, через тот же `NpcAction` с журналированием решений. Инференс в отдельном потоке; запрещён во время боя и загрузки чанков. Модель ≤3B квантизованная, выбор по видеопамяти при старте.

**Детерминизм — трёхуровневый** (Q73): генератор мира строго детерминирован (тест с первого коммита); симуляция детерминирована при null-LLM; с LLM — нет, осознанно. Тесты и репро багов — на null.

**Реплики** (Q71, Q74, Q80, Q81): реплика = идентификатор + условия + список сегментов (текст, интонация, громкость, скорость, тег). Реплика не знает, кто и когда её произносит; тембр — компонент NPC. Разметка одна на все языки. Пул реплик по ролям — оптимизация открыта.

**Озвучка** (Q69, Q75–Q79): два синтеза — выразительный оффлайн (`tools/voice_gen/`) и Piper онлайн для реплик LLM (невыразительный игнорирует мета-разметку). Готовое аудио в комплекте (Opus); досинтез при рассинхроне. Хеш на сегмент (текст + разметка + голос); пересинтез только изменившегося; склейка с кроссфейдом против швов на стыках.

## 6. Процесс разработки

**Команда:** лид (Opus 5) + три тиммейта на Claude Opus 4.8 (Q53): `core` (core+world), `render` (platform+render), `sim` (physics+anim+gameplay) (Q33, Q52). Границы зон = границы директорий, проверяются компилятором.

**Правила:** свод Quicky переносится целиком с правками — C++23, потолок файла ниже, null-физика остаётся; добавлены правила детерминизма, фиксированного шага, единиц измерения, запрета установки, владения директориями, обязательной визуальной проверки, пакетных ECS-операций (Q23, Q31). `header_check.py` + pre-commit.

**Контракты первыми** (Q38): этап 1 — только техспеки и заголовки публичных интерфейсов; лид сводит и вскрывает несостыковки. Контракт заморожен на этап; изменение — через групповой синк. `IRenderer` пишет лид сам до старта агентов (Q55).

**Техспека агента** — 7 разделов: зона, публичный интерфейс, внутреннее устройство, зависимости, план по шагам, чем проверяется, чего НЕ делает (Q35).

**Синки** (Q36, Q39): по изменению публичного интерфейса + групповой в конце этапа. Записи — `docs/devlog/` (один файл на синк, со скриншотами) + индексный файл с итогом в одно предложение.

**Git** (Q61): ветка на агента, слияние только на зелёной сборке, сломавший чинит немедленно. Три безуспешных подхода к проблеме — стоп и сообщение лиду.

**Визуальные тесты** (Q21, Q24): тур со скриншотами (перенос из Quicky), чек-лист на кадр; эталоны — позже. Правило: изменение картинки без прогона тура не принимается.

**Этап 2 — скелет** (Q37, Q51): окно, `IRenderer` (bgfx+null), камера, один плоский чанк, контроллер на Jolt, тур. Критерий: четыре скриншота, не чёрные, земля и горизонт на месте.

**Документы:** `GDD.md` + `TDD.md` + `NUMBERS.md` (единственный источник констант, из него генерируется C++-заголовок) (Q54).

## 7. Открытые темы

**Геймдизайн (отдельный гриллинг на играбельном каркасе):** детали боя, наполнение мира, префабы данжей, формат квестов, предметы/инвентарь, цикл дня и ночи.

**Техника (в техспеках агентов):** оптимизация пула реплик, стыковка аудио-сегментов, алгоритм генератора ландшафта, LOD, бюджет кадра, ввод, камера, профилирование, CI, пайплайн ассетов.

**Стриминг музыки.** Сегодня музыка декодируется ЦЕЛИКОМ в память — см. решение в §2, — и это перестаёт работать на слоёной адаптивной музыке. Отдельный путь загрузки (`MA_SOUND_FLAG_STREAM`) меняет контракт `IAudio`, значит идёт через групповую синхронизацию (правило 26), и ждёт этапа, которому слои действительно нужны. Дефект №1 из `reports/music-research.html` §8.

**Пользователь ресёрчит сам:** выбор моделей синтеза речи (Q76).
