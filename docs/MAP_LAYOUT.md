# MAP_LAYOUT.md — раскладка карт и демок

Контракт, на котором держится весь конвейер инструментов. Определён ДО демок,
чтобы зоны не расходились. Меняется только лидом (правило 25).

## Дерево на диске

```
assets/maps/
  <категория>/
    <карта>.map          # манифест карты (текст, в git — лёгкий, читаемый)
    <карта>.chat.jsonl   # двусторонний чат рядом с картой (см. ниже)
    <карта>.dfw          # ПЕЧЁНАЯ карта — появится с пекарем (пока нет; НЕ в git, в кэш)
```

- **Карта = файл-манифест `.map`** внутри папки-категории. Пользователь: «папки
  разные, и в папке я уже выбирал карту» — два уровня, категория → карта.
- **Манифест `.map` — в git** (рецепт, лёгкий). **Печёный `.dfw` — НЕ в git**
  (десятки-сотни МБ, раздувают историю; в35): пересобирается при первом запуске
  из манифеста и кэшируется локально (`cache/maps/`), с загрузочным экраном
  «подготовка объектов».
- **`chat/` НЕТ отдельной папкой** — чат живёт файлом `<карта>.chat.jsonl` рядом
  с картой, чтобы «коммент в демке» сам знал свою карту и её зону-владельца.

## Категории (список пользователя, в40)

`landscape` · `trees` · `bushes` · `fallen-tree` · `houses` · `light` · `water`
· `mountain` · `caves`

Каждую категорию ВЛАДЕЕТ своя зона (правило 25): trees ← флора, light ← свет/факела,
houses ← строитель, landscape/mountain/caves ← рельеф, water ← вода. Зона пишет
демки в СВОЮ категорию, лид следит за форматом. Новые категории заводит лид.

## Манифест `.map` (транзитный формат, до пекаря)

Текст, `ключ = значение`. Пример `assets/maps/landscape/valley.map`:

```
name = Долина у скалы-храма
zone = terrain
size_chunks = 4
# ИСТОЧНИК карты. Сейчас — генератор-стенд (мост, пока нет пекаря);
# позже source = dfw:valley.dfw (печёная карта).
source = stand:Testbed
description = Базовый ландшафт: долина, скала, деревни, вода.
built_commit =
```

Когда пекарь `.dfw` заведён — `source = stand:...` меняется на `source = dfw:<файл>`,
и браузер грузит печёное, а не генерирует. Мост нужен, чтобы браузер работал
end-to-end уже сегодня, до пекаря.

## Чат `<карта>.chat.jsonl` (двусторонний, в28/о1)

Append-лог, по строке-JSON на запись. Две роли:

- **человек → зона** (замечание на месте): `{"t":..., "who":"human", "text":"...",
  "capture":"<путь к снимку>", "trajectory":"<путь к записи>"}`
- **зона → человек** (самодокументация демки, правило о1): когда агент создаёт/меняет
  демку — пишет `{"t":..., "who":"<zone>", "text":"зачем демка, какая задача, что
  решено, как, на что смотреть чтобы убедиться"}`. Правило пользователя: демка
  сама объясняет себя.

`t` — счётчик/`game_seconds` для порядка (стенных часов в детерминированном коде
нет); реальную дату инструмент подставляет при сбросе. Ответы агента — короткие.

## Браузер редактора

Вход в «Редактор» (и в «Играть») открывает НЕ карту, а браузер:
**категории (папки) → карты (`.map` в папке) → открыть**. Прыгать сразу в карту
нельзя — это была ошибка первого каркаса, названная пользователем.
